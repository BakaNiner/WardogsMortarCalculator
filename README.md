# WARDOGS 迫击炮计算器

[English](#wardogs-mortar-calculator)

Windows 桌面工具：按快捷键读取游戏地图上的 X/Y 坐标，计算 L81 迫击炮的方位角、水平距离和 MIL。OCR 在本机运行，模型随程序打包。

本项目由 **GPT-6 Astra** 生成，并根据实际游戏截图及使用反馈迭代。它是非官方社区工具，与 WARDOGS 开发商或发行商无隶属关系。

## 下载与运行

便携版见 [GitHub Releases](https://github.com/BakaNiner/WardogsMortarCalculator/releases)。下载 `WardogsMortar-v<版本>-Windows-x64.zip`，完整解压后打开 `WardogsMortar/WardogsMortar.exe`。需要 Windows 10/11 x64，无需另装 Python。请保留整个文件夹及 `_internal` 目录。

## 使用说明

1. 启动后等待右上角显示“本地 OCR 就绪”。
2. 游戏使用无边框窗口模式，打开地图，把十字线指向迫击炮所在位置，按 **F1**。
3. 把十字线指向目标位置，按 **F2**。
4. 查看悬浮窗中的方位角、距离和 MIL，按方位角和 MIL 调整迫击炮；**F3** 切换悬浮窗显示。
5. 更换目标时重新指向目标并按 **F2**；移动迫击炮后，重新指向炮位并按 **F1**。

地图上的 X/Y 是十字线所指位置，并不自动代表玩家或迫击炮的位置；识别时请确保坐标文字完整可见。快捷键可在“设置”中修改。

设置保存在 `%LOCALAPPDATA%/WardogsMortar/settings.json`，日志位于同目录的 `app.log`。炮位和目标不会跨启动保留，避免下次进入游戏时误用旧坐标。

## 识别与隐私

按键触发时立即截取配置区域，后台串行执行 OCR。只接受带 X/Y 标签且具有两位小数的坐标，并校验文字位置与置信度。缺失、模糊或多组候选时提示重试，保留原坐标。手动修改、清空及后续同类任务会使旧识别任务失效。

OCR 模型在启动时预加载。模型随程序打包，识别无需网络连接。仅在触发时截图，不持续录屏；最近一次截图只保存在内存用于预览。应用读取屏幕画面，不读取游戏进程内存或修改游戏文件。

## 计算与射表

设炮位为 `(gun_x, gun_y)`，目标为 `(target_x, target_y)`：

```text
dx = target_x - gun_x
dy = target_y - gun_y
distance_m = hypot(dx, dy) * 100
azimuth_deg = degrees(atan2(dx, dy)) mod 360
```

北为 0°，东为 90°，南为 180°，西为 270°。两点重合时方位角无定义。MIL 在相邻射表数据间线性插值，仅在 132–684 米内返回；越界不外推。界面显示取整 MIL，计算过程保留原精度。

射表为社区平地数据，不含高差修正，游戏更新后可能需要重新校验。数据位于 [`wardogs_mortar/data/l81.json`](wardogs_mortar/data/l81.json)，含来源、获取日期与来源提交号。来源：[Apollyon / wardogs-calculator](https://github.com/apollyon-sys/wardogs-calculator/blob/e5b801ee17bbd2bdf49f8f9ac474173c65573b62/data/weapons.json)，许可见 [`licenses/Apollyon-MIT.txt`](licenses/Apollyon-MIT.txt)。

计算示例：炮位 `(80.00, 70.00)` → 目标 `(83.00, 74.00)` = **500 m / 36.87° / 461 MIL**。

# WARDOGS Mortar Calculator

[中文](#wardogs-迫击炮计算器)

A Windows desktop tool that reads X/Y coordinates from the game map with hotkeys and calculates the L81 mortar's azimuth, horizontal distance, and elevation in MIL. OCR runs locally, with models included in the application.

This project was generated by **GPT-6 Astra** and refined using game screenshots and user feedback. It is an unofficial community tool and is not affiliated with the developers or publishers of WARDOGS.

## Download and run

Find portable builds on [GitHub Releases](https://github.com/BakaNiner/WardogsMortarCalculator/releases). Download `WardogsMortar-v<version>-Windows-x64.zip`, extract it completely, and open `WardogsMortar/WardogsMortar.exe`. Windows 10/11 x64 is required; Python is not. Keep the complete folder, including `_internal`.

## How to use

1. Wait for “Local OCR ready” in the upper-right corner.
2. Use borderless windowed mode, open the game map, point the crosshair at the mortar position, and press **F1**.
3. Point the crosshair at the target position and press **F2**.
4. Read azimuth, range, and MIL in the overlay, then aim the mortar using the azimuth and MIL. Press **F3** to show or hide the overlay.
5. For a new target, point the crosshair at it and press **F2** again. After moving the mortar, point at its new position and press **F1** again.

The X/Y labels refer to the map crosshair position, which is not automatically the player's or mortar's position. Both labels must be fully visible when capturing. Change the hotkeys in Settings if needed.

Settings are stored in `%LOCALAPPDATA%/WardogsMortar/settings.json`, with logs in `app.log` in the same directory. Gun and target coordinates are not restored on launch, preventing accidental reuse in a later session.

## Recognition and privacy

Pressing a capture key immediately captures the configured region. OCR jobs run sequentially in the background. Only X/Y-labeled coordinates with two decimal places are accepted, with checks for spatial alignment and confidence. Missing, unclear, or ambiguous results ask you to retry while retaining previous coordinates. Manual edits, clearing, and newer captures for the same position invalidate older jobs.

OCR models load at startup and are bundled for offline recognition. Screenshots are taken only when triggered; the application does not continuously record the screen. The latest capture stays in memory for preview. The application reads screen pixels, without reading game-process memory or modifying game files.

## Calculation and firing table

For a gun at `(gun_x, gun_y)` and a target at `(target_x, target_y)`:

```text
dx = target_x - gun_x
dy = target_y - gun_y
distance_m = hypot(dx, dy) * 100
azimuth_deg = degrees(atan2(dx, dy)) mod 360
```

North is 0°, east 90°, south 180°, and west 270°. Bearing is undefined for identical positions. MIL is linearly interpolated between adjacent firing-table entries, only within 132–684 meters, without extrapolation. Displayed MIL is rounded; calculations retain full precision.

The community firing table assumes flat ground and does not correct for elevation differences. Game updates may require revalidation. [`wardogs_mortar/data/l81.json`](wardogs_mortar/data/l81.json) records the source, retrieval date, and source commit. Source: [Apollyon / wardogs-calculator](https://github.com/apollyon-sys/wardogs-calculator/blob/e5b801ee17bbd2bdf49f8f9ac474173c65573b62/data/weapons.json), licensed under [`licenses/Apollyon-MIT.txt`](licenses/Apollyon-MIT.txt).

Example: gun `(80.00, 70.00)` → target `(83.00, 74.00)` = **500 m / 36.87° / 461 MIL**.
